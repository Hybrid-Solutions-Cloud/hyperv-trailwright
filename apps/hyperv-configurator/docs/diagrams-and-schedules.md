# Diagrams and joined schedules

Review and exports provides management, physical, logical, network, storage and deployment views alongside the complete overview. A view includes its resource categories and directly connected context. Arrows show declared references, prerequisites, availability membership or stage targets; they do not imply discovered connectivity or completed deployment. Text-only provider contracts remain in the inventory rather than becoming guessed physical connections.

The package contains an editable draw.io file and PNG pages for every view. `diagrams/index.json` maps each PNG to its view, page, editable file, original resource IDs and relationship IDs. `diagrams/topology-graph.json` retains complete names, typed relationships and unresolved references. The original `topology.drawio` and `topology.png` filenames remain the overview entry points.

Resource pages contain at most 24 nodes and 12 connections. Relationships whose endpoints fall on different pages, or exceed a resource page’s connection limit, have separate relationship pages with both endpoints repeated. Numbered connections share a readable legend in the PNG and editable diagram. Each connection appears exactly once per view; the index identifies repeated context. This preserves diagrams for inventories larger than the previous 500-resource limit and bounds each PNG canvas. Large projects produce more pages. Full labels remain in the graph, editable file and accessible resource table; long raster labels wrap and show an ellipsis when they exceed three lines.

The preview offers view and page selection, fit-to-width or actual-size display, and resource/relationship tables for keyboard and small-screen use. Selecting shareable output updates the preview and package from the same sanitized project. Resource IDs are namespaced inside draw.io to avoid collisions with internal graph cells; original IDs remain in the graph and index.

The workbook and CSV schedules add joined IP/VLAN, address allocation, NIC/physical port, host interface, storage owner and dependency tables. These resolve resource names while retaining IDs, scoped addressing and exact quantities. A matching earlier address declaration and typed allocation are combined with both source references. Duplicate typed allocations remain separate for correction. Interface mappings use stable IDs even when display names repeat. Storage owner mappings show each disk allocation once without adding its capacity to the backing volume again. Generic inventory sheets preserve all other supplied fields.

All diagrams and schedules describe the design. Unresolved references, external placement, physical switch evidence and deployment acceptance require review; no resource or connection is created by exporting them.
