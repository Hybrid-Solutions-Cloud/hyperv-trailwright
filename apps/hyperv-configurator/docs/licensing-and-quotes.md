# Licensing assignments and quote review

Choose a reviewed manual quantity or an explicit physical-core/per-VM calculation for each license item. The assessment separates quantity, rights and price review. A known quantity can have an unresolved quote; an unfilled zero price never means free licensing. Included-use records remain commercial assertions supported by the licensing owner, not an automatic product installation entitlement.

## Calculated core models

The current calculation profile uses Microsoft's Commercial Licensing guidance for Windows Server 2025 and System Center server management. Select the product, core license edition, customer boundary and quote unit size separately. An installed host edition, a free-text SKU or a management product selection does not assign entitlements automatically.

For physical-core coverage, add one assignment for every applicable host, including reserve and failover destinations. Hardware sockets and cores come from its existing host record. Record peak virtual OSEs on that particular server and whether its physical OSE solely hosts/manages VMs, counts as another OSE, or is absent. Windows quantities concern Windows Server OSEs and Windows containers with Hyper-V isolation; System Center quantities concern the managed server OSEs. Review Linux/server management scope, hardware capacity and placement enforcement separately.

The base is the greater of physical cores, eight cores per processor and sixteen per server. Standard needs a complete additional base set for each additional pair of counted OSEs. Datacenter does not stack for additional virtual OSEs. Core-license requirements are kept separate from purchasable packs: the quoted item can use one-core, two-core or sixteen-core units. Spare nodes are not subtracted from licensing demand. These rules come from [Windows Server guidance](https://www.microsoft.com/licensing/guidance/Windows-Server-2025), reviewed 2026-09-11.

For per-VM coverage, assign explicit hosted server-VM records. Each VM contributes its vCPU count subject to an eight-core minimum, and the reviewed customer/product pool has a sixteen-core minimum. The calculation requires eligible subscription or active SA evidence covering the design date. The physical and per-VM models grant different rights; Datacenter licensed per VM does not grant unlimited VM coverage. [Core licensing guidance](https://www.microsoft.com/licensing/guidance/Core-based-licensing-models), reviewed 2026-09-11.

One automatic per-VM pool is allowed per customer/product so its minimum is not repeated. Use a reviewed manual calculation for mixed agreements/editions, partial external pools, SPLA/OEM, hosted/outsourcing or other unmodeled rights. A host and a VM are not interchangeable assignment targets. Duplicate assignments for the same product/model block the quantity instead of adding demand twice. OME appliances, external services and dedicated physical components are not offered as server-VM targets.

## Resource coverage and supporting SQL

Use **External and management physical license inventory** for a dedicated physical management server or an external Hyper-V/VMware host that is absent from the Hyper-V host inventory. Record exact provider/native identity, sockets, physical cores and reviewed responsibility. The same physical-core assignment calculator can select that server. Do not duplicate a host already inventoried; duplicate scoped identities and UUIDs require correction. These inventory rows add no VM capacity and request no infrastructure creation.

**Resource licensing coverage** links a license item, a resource and an assignment or reviewed manual/provider contract. Normal, maintenance and failover destinations remain explicit. Per-VM assignments cover only the selected VM. Different physical destinations are allowed; overlapping allocations on the same destination require consolidation. The largest mapped guest set for each host/scenario cannot exceed its declared peak OSE count. Provider and dedicated physical management contracts remain distinct from guest VM assignments. Unmapped resources remain visible even when every listed price is known.

**System Center services using covered estate** links VMM and SCOM to the same reviewed System Center item. Each estate must identify managed assignments or external coverage. Service links and workload maps add no quantities. The management server's Windows OS coverage remains separate. Microsoft's [System Center licensing comparison](https://www.microsoft.com/en-us/licensing/product-licensing/system-center) lists shared management components and supporting SQL Server Standard runtime rights; reviewed 2026-09-11.

For every SQL item, add **SQL usage and licensing scope** and its **SQL workload rights map** before treating the purchase gap as reviewed. This includes separate SQL quotes so an unassigned extra item cannot silently duplicate an existing SQL charge. Review each SQL server OSE, every instance, database/reporting role, release, edition, HA/failover use and hosting contract. The current included-use assessment requires Standard, matching VMM/SCOM workloads, the same reviewed customer boundary and a commercial System Center source with a positive resolved quantity and rights. An unknown source price does not invalidate otherwise reviewed rights, but the overall estimate stays partial. Missing source rights or quantities withhold SQL purchase credit.

Mixed/unrelated workloads, Enterprise editions or full AG features cannot receive this included Standard runtime credit. Select separately licensed SQL and review its quantity, quote and exact features instead. Preserve the unused source reference for later review; it is omitted from the active coverage plan. Provider SQL requires an explicit hosted contract. A provider-included SQL item additionally needs a matching provider program and entitlement term, inclusion/exclusion evidence and a reviewed no-charge quote; it does not inherit System Center supporting-technology rights. Duplicate SQL OSE records and duplicate workload names within one scope require consolidation. Existing included-use notes alone no longer produce a zero purchase gap.

The [System Center Product Terms](https://www.microsoft.com/licensing/terms/en-US/productoffering/SystemCenterServer/OL) restrict supporting technology by use and OSE/server scope and refer outsourced hosting to separate terms. The owner must review the exact agreement, OSE allocation, all instances and HA/DR rights. This model records that review; it does not derive a general entitlement for every SQL VM from a System Center component selection. Other products' included SQL and noncommercial programs require a separately reviewed SQL item. Sources reviewed 2026-09-11.

Schema29 adds five empty coverage collections. Earlier values and commercial rights remain intact; no target, supporting SQL right or placement is inferred. The same active coverage plan appears in `plans/license-coverage.json`, `reports/license-coverage.md`, the licensing assessment, joined workbook schedule and full design Markdown. Canonical project/YAML, generic PDF and inventory worksheets retain all collected records. Sanitized exports remap references and remove commercial evidence; their rights remain unresolved.

## Existing coverage and quote evidence

Each item now records its program family, exact agreement reference, rights owner and applicable terms evidence. Entitlement terms (perpetual, active SA, subscription or provider supplied) are independent of the quote's billing period. Record the term start, any required end date, original assignment date, and mobility/failover evidence. A historical assignment can precede an SA renewal. Expired SA can be reviewed as perpetual rights where applicable; that decision does not retain per-VM eligibility.

Automatic core calculations require the commercial program family. Other programs use an explicitly reviewed manual quantity. Hosted items also require a named provider/customer/outsourcing review. Selecting a provider program requires a matching provider entitlement term. The application checks consistency; it does not certify contractual eligibility.

Fixed assignments, eligible per-VM mobility, individually reviewed exceptions and provider assignments remain distinct choices. Moving a VM is not proof of a transferable license. Review server-farm boundaries, frequency, destination coverage and the applicable agreement. See [Microsoft's server virtualization guidance](https://www.microsoft.com/licensing/guidance/Server_Virtualization), reviewed 2026-09-11. No universal reassignment or DR exemption is inferred from an exception selection.

Activation has its own method, external runtime reference and owner/prerequisite evidence. Missing activation details produce implementation findings without erasing a reviewed purchase quantity. An activation selection cannot resolve missing entitlement evidence. Product-key-shaped text in the activation reference is rejected on save/import; enter external references, never keys. KMS, ADBA, MAK and AVMA are collected choices, not execution or compatibility certification. For example, [AVMA has specific host and guest prerequisites](https://learn.microsoft.com/en-us/windows-server/get-started/automatic-vm-activation); record the applicable version review separately.

Available covered units are allocations from a named entitlement pool, measured in the same units as the quote. Record the pool's total, agreement, product/edition, customer and unit basis consistently. Allocations across license items cannot exceed the pool total. The same pool identifier with inconsistent metadata blocks credit. Separate purchases for VMM/SCOM and supporting SQL still need an included-use review; this assessment does not infer those rights from installation choices.

Record a quantity/assignment review and date. Then choose a dated price quote or confirmed no additional charge, supplying its evidence reference, date, currency and period. A priced quote requires a positive price; a no-charge quote requires zero. An unknown quote remains unresolved even when the entered number is zero. Review and quote dates cannot be later than the project's assessment date. Per-VM subscription/SA expiry must cover that date. Opening a historical design does not silently substitute today's rights or rates; editing updates the project date.

Purchase gaps subtract reviewed covered units first. Currency and perpetual/monthly/annual periods remain separate. Totals identify unresolved items and show only the known estimate; a partial total is not a complete project budget. Estimates retain up to six decimal places. Taxes, discounts, term conversion and invoice rounding belong to the actual quote. No Surveyor price book or private customer defaults are copied into this tool.

## Reports and migration

The same assessment appears in the website, `plans/licensing-assessment.json`, `reports/licensing.md`, design Markdown/PDF, workbook purchase gaps/calculations/totals and CSV schedules. `environment/licensing.yml` carries both license items and explicit assignments. The assessment identifies its project revision, design date, rule profile and sources.

Schema 9 migrates older items as manual quantities with unreviewed quote status and no invented entitlement pool or assignments. Existing quantities, rates and descriptive evidence remain intact. Their new review fields must be completed before treating an old estimate as reviewed. Shared exports retain architecture and numeric quantities but scrub customer, entitlement and commercial evidence, so their operational review remains unresolved.

Access, SQL, Azure and dependency scope records capture the owner's review alongside these calculations. Exact agreement, version, outsourcing and assignment eligibility still require their referenced evidence; a successful calculation is not an entitlement certification.

The commercial-rights migration adds unanswered fields to earlier projects. Existing quantities, evidence notes, dates and coverage values remain unchanged. Until the new rights review is completed, automatic purchase gaps remain unresolved. Sanitized exports remove the underlying evidence and cannot retain a resolved rights or activation review. The same contract is included in assessment JSON, licensing YAML/Markdown, design reports and inventory worksheets.

## Access, Azure and feature dependencies

**Access rights and audiences** identifies the actual use, distinct users/devices or reviewed server scope, product versions, suite equivalence and overlap evidence. A scope has one license item, quoted as one unit per counted user, device or server. Existing allocations reduce the purchase gap. Use a stable audience identifier to detect repeated charges; different audience identifiers still require the owner's overlap review. RDS additive access links to a reviewed Windows base access item covering the same customer, audience and counting unit. Base rights uncertainty withholds the RDS credit; an unknown base quote does not invalidate otherwise reviewed rights. Mixed or alternative allocations require a separately reviewed access kind. [Microsoft CAL guidance](https://www.microsoft.com/en-us/licensing/product-licensing/client-access-license) distinguishes user, device, External Connector and suite rights; [RDS guidance](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/rds-client-access-license) adds version and deployment considerations. Reviewed 2026-09-11.

Subscriber access requires an explicit SPLA or provider contract, applicable term and unique authorized user/device scope. Product applicability and reporting remain in the agreement review; no SAL requirement or entitlement is inferred merely from hosted placement. See [Microsoft SPLA guidance](https://www.microsoft.com/licensing/guidance/SPLA), reviewed 2026-09-11.

**Azure service meters and benefits** maps each enabled service to a representative host, guest or resource and a complete billing scope. Enter exact meter/SKU, region, unit, charge period, consumption estimate, ingestion and retention. The required units and quote must use that same unit and period. Decimal Azure quantities and covered units support up to six decimal places; core and access quantities remain integral. Existing benefits must be explicitly allocated or reviewed as full inclusion. Meter-unit pools cannot be reused across different meters, regions, periods or units. Monetary credits, commitments, tiers and conversions require a separately reviewed estimate rather than implicit arithmetic. [Arc pricing](https://azure.microsoft.com/en-us/pricing/details/azure-arc/core-control-plane/) distinguishes core capabilities from enabled add-on services; [Monitor pricing](https://azure.microsoft.com/en-us/pricing/details/monitor/) separates ingestion, retention and other meters. No live rate is hard-coded. Reviewed 2026-09-11.

**OME, SDN and third-party license dependencies** maps selected plugins, features, hosting, backup and network dependencies to a license item and consuming resource. Record exact versions, covered device inventory, entitlement tier and exclusions. Multiple features can reuse one covered entitlement without creating another license row or charge. Duplicate feature allocations require consolidation. OME plugin rights do not license the host OS; an SDN Windows dependency must point to an actual assignment or resource coverage mapping. Dell's [OME 4.4 licensing guide](https://www.dell.com/support/manuals/en-us/dell-openmanage-enterprise/ome_4_4_online_help_user_guide/licensing?guid=guid-615a018a-ebd8-4352-92e0-f7b532dbfa7f) distinguishes Advanced/Advanced+ plugin requirements and additional iDRAC prerequisites. Review the selected appliance/plugin release and device entitlement explicitly; no tier is inferred. Reviewed 2026-09-11.

Schema30 adds three empty collections without inventing any coverage. Each access, Azure, OME, VMware, backup or other dependency item requires a matching scope before purchase credit. The shared coverage JSON, YAML, design report, PDF and inventory workbook/CSV retain these records, and sanitized exports remove their commercial evidence. Unmapped resources and unlisted dependencies still require review even when every entered item has a price.
